1. 总览: 原生 Runtime 控制面

code_minions 没有把 agent orchestration 交给某个 provider SDK。CLI/Web 进入 Engine 后，workflow DAG、skill runtime、agent loop、tool execution、quality gates、run events 和 failure classification 都在本地 Python runtime 中执行。LLM 只是一个可替换的 chat(messages, tools, ...) 能力。

2. AgentLoop 时序: 模型调用不等于 Agent 控制权

AgentLoop 是本地状态机。模型只负责下一条 assistant message 或 tool call；是否继续、能否调用工具、是否超过轮次、如何解析最终 JSON、如何重试 parser error，都由 code_minions runtime 决定。

3. Provider 无关边界

上层 runtime 使用 code_minions 自己的内部类型：Message、Tool、ToolCall、Response。Provider-specific 的差异只允许出现在 adapter 层：模型名拼接、tool schema normalization、temperature/reasoning defaults、MiniMax HTTP response 解析等。

4. Durable Observability: run_events 是可审计运行日志

关键变化是“先记录开始，再进行长操作”。所以当 run 卡在 provider 请求、tool call 或测试命令里，Web UI 和数据库里会有 in-flight 证据，而不是只能看到 step 仍然 running。

Start

llm_call_started, tool_call_started, command_started 在长操作前写入。

→
Execute

Provider call、local/MCP tool、delivery gate、test/build command 执行。

→
Finish

成功写入 duration、usage、stop_reason、tool names、result size。

Fail

失败写入 classification、error、retryable、exit_code 或 compact evidence。

Redaction

redacted_event_payload 在落库前调用 redact_secrets，避免 API key 或 secret 被持久化。

Compact Payloads

LLM event 记录 messages_count、prompt_chars、tools_count，不保存完整 prompt。

SSE Replay

Web 订阅会先 replay 最近 100 条 run_events，晚打开页面也能看到当前 runtime activity。

5. Tool Runtime: 让工具调用也进入同一个控制面

模型只能“请求”工具；工具是否允许、能否并发、输出如何截断、路径/命令是否越权，全部在 runtime 里处理。

Read-only Tools

Read 和 Glob 标记为 read-only + concurrency-safe，可以在同一轮并发执行。

Mutating Tools

Write、Edit、Delete、Bash 默认串行，避免并发写文件。

Capability Gates

tool-capabilities 约束 Bash allowlist 和 path allowlist，违规前置拒绝。

Result Budget

长工具输出保留 head + tail，中间插入 omitted marker，避免 context 被日志淹没。

6. implement-with-tdd: 同一个 AgentLoop 上的工程闭环

implement-with-tdd 不是单独一套 provider loop。它复用 AgentLoop，但在 tool handler、final parser、after_tool_round 和外部 gate/review loop 上叠加工程约束。

7. 失败分类: Provider 事故和实现失败分开

Engine 捕获异常后读取 run_events，调用 classify_failure。这让 “provider timeout/503/rate limit” 不再被误判成 generated app 的实现失败。

Classification 典型来源 下一步 关键事件或文本
provider_unavailable LLM timeout、503、rate limit、connection reset、provider overload。 稍后重试，或切换 llm.roles 中对应角色 provider/model。 llm_call_failed + provider_timeout, provider_unavailable, provider_rate_limited
workflow_systemic provider schema/bad request，或工作流 payload 被 provider 拒绝。 修 code_minions 的 provider payload/schema handling 后再跑。 schema_incompatible, bad_request
implementation_fixable 测试失败、构建失败、AI review blockers、runtime gate findings。 继续 implement/self-heal，把失败证据喂回实现循环。 pytest, npm, review blocker, gate.findings
acceptance_failed 浏览器验收或产品验收失败。 检查 screenshot/e2e artifacts 和 acceptance_items，修产品行为或 UI。 browser_acceptance, acceptance_failed, accepted: false

8. 关键源码映射

下面是这张图对应的核心实现点。读这些文件可以从入口一路追到 provider adapter 和 Web 展示。

engine/agent_loop.py

共享 agent loop：context compaction、LLM start/finish/fail events、tool rounds、max limits、final parser retry。

engine/llm_transport.py

provider 异常分类：timeout、503/overload、rate limit、auth、schema incompatible、bad request、connection error。

engine/tool_runtime.py

工具 metadata、并发安全策略、工具输出预算与截断。

engine/tool_executor.py

本地/MCP 工具执行、tool start/finish/fail events、workspace mode 与 capability allowlist。

engine/observability.py

event 常量、duration、prompt size estimation、secret redaction、LLM payload helper。

engine/context_compaction.py

CODE_MINIONS_CONTEXT_BUDGET_CHARS 和 compacted message 生成。

engine/failure_classification.py

从 run_events、step output 和 error text 推导 user-facing failure classification。

llm/litellm_backend.py

provider adapter：内部类型和 LiteLLM/OpenAI-style/MiniMax HTTP payload 的双向转换。

9. 一句话结论

这套机制是 code_minions 原生实现的 provider-neutral agent runtime：workflow 和 agent loop 的控制权在本地 Engine/AgentLoop；provider 只提供一次 chat 调用能力；工具、验证、事件、失败分类和交付报告都由 code_minions 自己持久化和裁决。
