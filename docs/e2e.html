code_minions E2E 与 Web UI 验收机制

当前实现把 e2e 拆成稳定 CI、Web route/SSE、可选真实浏览器 smoke、人工 dashboard 验收和 PRD 产品验收 evidence。真实浏览器覆盖关键路径，通用 PRD 验收主要依赖目标项目测试、delivery gates 和 product acceptance。

分层验证总览

越往右越接近真实用户体验，但运行成本和脆弱性也更高。
L0

pytest + ruff

默认 gate。验证 unit、integration、coverage、lint，保持普通开发循环稳定。

L1

Engine e2e

Engine 直接跑内置 workflow，使用 fake LLM 和真实 store/workspace。

L2

Web route / SSE

TestClient 和 ASGI 流测试覆盖页面、表单、控制按钮、事件流。

L3

Playwright smoke

可选真 Chromium：空列表 -> New Run -> hello-world -> detail success。

L4

人工验收

phase-c-acceptance.md 覆盖 dashboard 的 cancel、resume、orphan scanner 等完整路径。

Dashboard 交互测试机制

自动化覆盖 HTTP/ASGI 行为，真实浏览器只跑最高价值路径。
FastAPI route tests

tests/unit/test_web_routes.py

列表页、详情页、step 输出、gate findings。

tests/unit/test_web_start.py

新建 run 页面、HTMX inputs fragment、文件 datalist、表单提交。

tests/unit/test_web_controls.py

Cancel / Resume 的 HTTP 行为和 Engine 调用。

SSE and background run

/runs/<id>/events

ASGI 级测试直接驱动 scope、receive、send，避免无限 SSE 被 TestClient 缓冲。

  • 验证 text/event-stream
  • late subscriber 收到 step snapshot
  • terminal run 收到 run.finished
v

BackgroundTasks

Web 发起 run 后在同一进程 EventBus 推送状态，detail 页通过 SSE 实时刷新。

Real browser smoke

tests/browser/test_web_smoke.py

临时 git repo 中启动真实 code-minions web，Playwright Chromium 执行关键路径。

  • 打开 dashboard
  • 选择 hello-world
  • 填写 name 并启动
  • 等待 run 和 step success

失败证据

失败时保存 full-page screenshot 到 pytest 临时目录。

CLI 启动的 run 不会把实时事件跨进程推到 Web dashboard。浏览器刷新后能看到最终状态；Web 页面发起的 run 才通过同进程 EventBus 走实时 SSE。

PRD Web UI 产品验收链路

这里验证交付物和 PRD/delivery profile 对齐，不是通用浏览器点击机器人。
PRD

parse-prd

解析 goal、features、constraints、delivery profile。

planning

任务拆解

plan-tasks 或 stack planner 让每个 task 继承产品约束。

implementation

implement-with-tdd

生成目标项目测试并运行 stack test command，例如 Vitest 或 pytest。

gates

Delivery gates

检查项目形态、imports、routes、依赖、已知 runtime drift。

acceptance

Product acceptance

输出 accepted、acceptance_items、verifier_rounds、报告表格。

判断一次 Web UI PRD 是否验收充分，要同时看目标测试是否覆盖真实用户行为、delivery gates 是否无 blocker、product acceptance 是否 accepted，以及高风险 UI 是否补了浏览器或人工证据。
