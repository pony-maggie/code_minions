End-to-End Workflow

prd-to-commit.yaml runs in workspace.mode: git-worktree
Input

PRD + Delivery Contract

用户提交 prd.md。推荐写清 delivery_profile：artifact kind、language、framework、build system、test command、required files、forbidden languages。

parse-prd

Structured Spec

LLM 将 PRD 解析成 goal、features、non-functional、constraints、users、questions 和规范化后的 delivery profile。

plan-tasks

Task Plan

拆成有依赖关系的 task。每个 task 会继承同一个 delivery profile，避免后续实现偏离 PRD 指定技术栈。

for_each

implement-with-tdd

每个 task 在 run worktree 里独立执行 TDD、自修复和提交。成功的 iteration 会产出 commit SHA。

acceptance

Product Acceptance

实现完成后，product-acceptance-review 再用 PRD 和 delivery profile 做产品级验收。

report

Report + Branch

compile-report 聚合结果。用户从 .devflow/runs/<id>/worktree review，再 merge code-minions/<run-id>。

Context

Project Context

注入 root markers、AGENTS.md 摘要、权威构建文件，如 package.json、project.yml、pyproject.toml。

Delivery Guidance

Profile-Specific Prompt

React/Vite、Swift/XcodeGen、turn-based board game 等会获得专门的实现约束，例如 jsdom、tsc --noEmit、GENERATE_INFOPLIST_FILE。

Core Harness

Coder Loop with Local Tools

LLM 可以调用 Read、Write、Edit、Delete。写入后 harness 会要求模型停止继续调用工具并返回小 JSON，文件系统变化是事实来源。

Self-Heal Loop
Generate tests + code
Delivery profile check
Install + typecheck + test
Failure playbook hint

如果任何门禁失败，失败输出和 playbook hint 会回灌给 coder，直到 green 或达到 repair budget。

Execution Profile

Stack-Aware Commands

React/Vite 运行 npm install、npx tsc --noEmit、npm test。Swift/XcodeGen 运行 xcodegen generate、xcodebuild test。

Commit Boundary

Green Before Commit

只有通过门禁后才 commit。node_modules、dist、coverage、*.xcodeproj 等生成物会被排除。

Gate Stack

从 spec 到 product acceptance 的多层门禁

Spec Gate

PRD 中的 delivery_profile 是产品交付契约。

  • kind / language / framework
  • required_files
  • forbidden_product_languages
  • test_command

Workspace Gate

代码生成发生在隔离 worktree，而不是直接改当前项目目录。

  • .devflow/runs/<id>/worktree
  • code-minions/<run-id> branch
  • status / resume 以 run database 为准

Delivery Profile Check

validate_delivery_profile 在测试前做静态完整性检查。

  • required files exist
  • forbidden language files absent
  • Swift tests not inside product sources
  • XcodeGen targets have Info.plist
  • React/Vite has jsdom and resolvable imports

Execution Gate

按技术栈执行确定性命令，而不是让模型声明成功。

  • React/Vite: install → tsc --noEmit → test
  • Swift/XcodeGen: generate → xcodebuild test
  • Python: python -m pytest -q
  • Go: go test ./...

Failure Playbook

把长堆栈翻译成可执行修复提示，降低 self-heal 试错成本。

  • missing Vitest / missing jest-dom
  • Testing Library duplicate DOM
  • Vitest jest is not defined
  • Vite unresolved relative import
  • XcodeGen duplicate outputs / missing Info.plist

Review Gate

测试 green 后可进入 ai-code-review，major/blocker 会回灌给 coder。

  • reviewer loop
  • blocker / major only blocks
  • review skipped is allowed by policy

Product Acceptance Gate

单 task green 不等于产品完成，最终还要对照 PRD 验收。

  • delivery profile evidence
  • task coverage
  • blockers and warnings
  • artifact-level status in report

Landing Gate

成功 run 仍需要用户 review worktree，再 merge branch。

  • inspect commits and report.md
  • rerun project verification
  • merge branch, not manual copy

Key Point

tests never green is a wrapper, not a root cause

Recent React/Vite runs all ended with the same outer error, but the inner failures moved from missing test runner, to jsdom, to cleanup, to relative imports, to Vitest mocks, to TypeScript interface drift. The harness hardening strategy is to promote each discovered class into an earlier deterministic gate or a sharper self-heal hint.

  • Earlier gates reduce expensive LLM repair cycles.
  • Failure playbook turns noisy logs into actionable instructions.
  • Delivery profile keeps the generated artifact aligned with the PRD.
  • Product acceptance keeps green tests from masquerading as complete product delivery.
This diagram reflects the current local architecture after the recent React/Vite, Swift/XcodeGen, failure-playbook, and typecheck hardening work. It is intentionally focused on the harness and gates, not on every CLI/Web/store detail.
